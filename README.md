# 攻伐战争 ⚔️

> 也可以直接在 [DBX](https://github.com/t8y2/dbx) 里玩：插件版 **AggressiveWar** 把同一套核心装进了编辑器，
> 外面套了一层 SQL 工作台伪装（老板键 + 失焦自动切换），并内置局域网联机。
> 插件仓库：https://github.com/chenjie1024/DBX-AggressiveWar

**区域征服 · 回合制 · 数字兵力** —— 极简文明类策略游戏。

棋盘由**不规则区域**拼成，每个区域用一个**数字表示兵力**（没有小兵、没有路线）。玩家在自己的回合增援、进攻相邻敌方区域、调兵，消灭所有对手即获胜。支持 **1v1 与 1vN**，当前为本地人机对战 Demo。

### 地图
- **6 套地图模板**：**地球（真实板块）** / 世界地图 / 华夏大陆 / 大陆 / 群岛 / 环形大陆。陆地按模板划分，再在陆地上用**网格 Voronoi** 切出不规则区域；海洋为背景（深海渐变 + 海底网格 + 海岸线）。
- **地球模板**：`packages/core/src/earth.ts` 用**经纬度多边形**描述各大洲板块（北美 / 格陵兰 / 南美 / 非洲 / 欧亚 / 澳洲 / 南极 + 马达加斯加、不列颠、日本、新西兰、印尼、菲律宾、冰岛、斯里兰卡、古巴、新几内亚），按等距圆柱投影栅格化成陆地掩码 —— 全部写在代码里，无外部数据文件；纵向裁到 84°N~70°S（两极在等距投影里会被严重放大）。陆地占比约 33%，可辨认出七大洲。
- **地图网格 72×40**（早期 56×30，放大约 1.7 倍）：模板按原生分辨率等比缩放，单块区域更大、地图更开阔；可选 **20 / 28 / 36 / 44 / 52** 区。
- **跨大陆「海路」**：不同陆地之间的最短缺口自动连边，保证区域邻接图**全图连通**；海路在地图上用 🌊 标注。
- **区域命名**：每个区域按地理分布就近取**真实地名**（阿拉斯加 / 高卢 / 江南 / 撒哈拉 / 澳洲东部 …共 57 个锚点），侧栏与战斗日志都显示地名。
- **无主之地**：未占领区域显示为**灰色色块**（按地形略作明暗区分），一眼可辨「可抢」。

### 侦查兵 🕵️
- **派侦查兵**：选中己方区域（需 ≥ 6 兵）→ 点 **2 格内**（按邻接跳数，含海路）的敌方/中立区域 → 确认后**消耗 5 兵 + 1 次行动**，探明**目标区及其所有相邻区**的兵力。
- 情报是**快照**：记录「第几回合看到多少兵」，之后即使该区域离开视野，地图上也会用小兵图标 + 数字显示（超过 5 回合标记 `~` 表示已过时），侧栏显示「🕵️ 情报 第 N 回合 · K 兵」。
- 地图上可侦查的目标用**青色虚线**高亮；日志记录「【秦】从阿拉斯加派出侦查兵，探明五大湖及周边 5 区的兵力」。

### 局域网联机 🌐
三种方式，菜单里可选：

**0. 📱 本机开房（手机当服务器 · 热点直连）** —— 只需要 APK，不需要电脑
- App 内置了一个**零依赖的 Java 中继**（`android/.../HostServer.java`）：HTTP 静态服务（直接托管 APK 里 `assets/www`）+ 手写 RFC6455 WebSocket（握手 / 掩码 / 126-127 扩展长度 / 分片续帧 / ping-pong）。
- **不跑游戏规则**：只做「分配房间码与席位 → 广播 begin（种子+配置+席位）→ 把每条 act 指令编号后广播回所有人」。规则在各台手机本地跑（锁步），所以不用把 TS 核心移植到 Java。
- 用法：A 手机开热点（系统设置里打开即可）→ 游戏菜单选「📱 本机开房」→ 创建房间 → 菜单/通知栏会显示 `http://<房主IP>:8080/`；其它手机连 A 的热点，浏览器打开这个地址，输入房间码（或直接用带 `?join=房间码` 的地址）→ 房主点「开始对局」。
- 前台服务（`HostService`）保证 A 手机切后台/锁屏时中继不掉线；通知栏常驻"局域网房间运行中"。

**A. 直连房间（锁步 · 转发式）**
- 与上一种同一套协议，只是中继在**电脑**（`npm run lan` 起的 `/relay`）或另一台已开房的手机上。
- **为什么可行**：核心是**种子随机**（`mulberry32`，无 `Math.random`/`Date.now`），RNG 状态随存档保存 → 同种子 + 同指令序列 = 逐字节相同的状态（`tests/world.test.ts` 的「锁步确定性」用例把这条钉死了，含 AI 回合与中途快照接力）。
- 中继给后加入者补发 begin + 全部历史指令，**掉线重连自动追平**。
- 缺点：没有服务端判定（防作弊弱），适合熟人局。

**B. 电脑服务器（服务端权威）**
- `packages/server/src/lan.ts`：服务端持有唯一 Game 实例，客户端只发指令 + 渲染，服务端校验回合与合法性 —— 防作弊强，但必须有一台跑 Node 的设备。

**用法（电脑当中继）**：`npm run lan`（= 构建前端 + 启动后端，监听 `0.0.0.0:3000`，同时托管网页 + `/relay` + `/ws`）→ 手机连同一 WiFi/热点，浏览器打开 `http://<房主IP>:3000/`，输入 4 位房间码。房间最多 6 方，人类加入会把 AI 席位换成人类。

|---|---|---|---|
| 城池 | 🏰 | +4 | +1 |
| 矿区 | ⛏️ | +2 | 0 |
| 农场 | 🌾 | +1 | 0 |
| 平原 | 🌿 | +1 | 0 |
| 森林 | 🌲 | 0 | +1 |
| 山地 | ⛰️ | 0 | +1 |

**特殊设施**（每区**每种各可建一个**，可叠加；金色光环 + 图标，地图上竖排显示）：🏛️兵营（每回合额外 +2 兵力）、🛡️要塞（防守额外 +2 骰）、💰宝库（占领后下一回合该区 +3 兵力）。每个消耗 1 次行动 + 5 兵，所以把一个区域打造成"满配"要 3 行动 + 15 兵。侧栏的建造区只列出**本区还没建过**的设施，并逐条写清效果；AI 也会建造（前线优先要塞、后方优先兵营/宝库，每回合最多 1 次、兵力富余时才动手）。
（旧存档兼容：v7 及以前的单设施 `special` 字段会在读取时自动迁移成数组，见 `serialize.ts`。）

### 回合与行动
- **回合制**：回合开始自动为当前方每个区域增援兵力。
- **行动次数**：每人每回合 **10 次行动** —— **调兵算 1 次、进攻算 1 次**（与兵力数量无关）。
- **进攻**：选中己方区域（兵力 ≥ 2）→ 点击相邻敌方/中立区域 → **Risk 式骰子战斗**（进攻最多 3 骰、防守最多 3 骰，骰数受兵力与加成的较小值限制），胜则占领并推进兵力。
- **调兵**：选中己方区域 → 点击相邻己方区域 → 弹窗**自选调动数量**（数量不限，可一次全部调走、原地留 1）。
- **战斗地形修正**：防守骰 = 地形加成 + 要塞 + 筑城术政策；**跨海进攻 -1 骰**（航海术政策可免除）。

### 平衡机制
- **领地加成**：每 **4** 块区域使每区额外 **+1** 兵力，最多 **+4**。
- **劣势补贴**：只给区域数**最少**的一方，按与领先者的**差距**每落后 1 区 +1，封顶 **+4**（落后越多补得越多）。
- **占领损耗**：占领后额外损失 1 兵，抑制「赢家通吃」。
- **难度加成**：困难档 AI 每区额外 +1。

### 平衡实测（`npm run balance -- 80`，80 局/难度 · 28 区 · 2 AI · 上限 100 回合）

| 难度 | 先手胜率 | 平均回合 | 超时率 | 领先者夺冠率 |
|---|---|---|---|---|
| 简单 | 32.5% | 73.7 | 40.0% | 62.0% |
| 普通 | 40.0% | 64.3 | 17.5% | 56.8% |
| 困难 | 32.5% | 54.9 | 15.0% | 61.0% |

> ⚠️ 上表是「每区最多一种设施」时代的基线。改成**每区每种各一个**（可叠加）后，40 局/难度复测：
> 先手胜率 27.5 / 45.0 / 25.0%，平均回合 76.6 / 74.2 / 61.8，**超时率 50 / 40 / 32.5%**。
> 原因很直观：兵营 +2 产兵与要塞 +2 防守骰现在能**叠在同一个区域**上，双方领地都越来越硬，推进变慢、更容易打满 100 回合。
> 想把节奏调回从前，可任选其一（都还没做，等你定）：① 建造成本 5 → 8 兵；② 每区最多两种设施；③ 兵营产兵 +2 → +1；④ 回合上限 100 → 120。

> 3 人局的公平基准为 33.3%，先手胜率 32.5–40% 说明**先手优势很小**。
> 加入季节/天气后，**领先者夺冠率从 68–87% 降到 57–62%**（正好落进理想区间 40–65%）—— 随机天时让"顺风局"不再一路平推，冬天产兵 -1 也会拖慢领先方的节奏。
> 简单档超时率偏高（40%）是因为简单 AI 进攻门槛高（1.3×）+ 冬季减产，推进更慢；对玩家而言，回合上限结算按积分算，通常仍是对玩家有利。
> 胜利条件改成「占领全图」后，超时结算从 37–55%（上限 60 回合）降到 15–17.5%（普通/困难，上限 100 回合）。
> 调优手段（历史）：领地加成 3块/+5封顶 → **4块/+4封顶**；劣势补贴从固定 +2 → **按差距缩放（封顶 +4）**；帝国政策从「每区 +2 兵」→「每区 +1 兵 +2 行动」；新增**占领损耗**；城池产兵 +3 → **+4**。

### 战争迷雾（开局可在菜单开关）
- **视野规则**：己方区域 + **相邻一圈**为「可见」；历史上探索过的区域为「已探索」（记住地形、地名与归属，显示为**阴影**）；从未到达的区域**全黑**。
- **情报表现**：不可见区域的兵力用 **`?`** 代替，地形/特殊/首都/围城等图标与威胁标记一并隐藏；悬停提示变为「兵力未知」；右侧详情面板对未探索区域只显示「🌫 未探索区域」，已探索但当前不可见的区域显示「兵力 `?`（已离开视野）」。
- **势力详情变成情报**：其他势力的「区域数 / 总兵力 / 城池」只统计**已探索**区域，并以 **`≈`** 前缀标注（例：`≈3区 · ≈21兵`），随你推进而逐渐逼近真实值。
- **视野扩张**：占领新区域后立刻揭开其相邻一圈；失去边境区域时，只与它相邻的区域会重新退回阴影。
- **AI 不受迷雾限制**（设计取舍）：AI 仍然全知，迷雾只影响人类玩家的视野与情报显示 —— 好处是**平衡与单机体验不受影响**（`npm run balance` 结果与未开迷雾时一致），代价是 AI 不会「摸黑」。
- **开关**：菜单勾选「战争迷雾」，选择会记在本地（`localStorage: gongfa-war.fog`），读档沿用当前选择；关闭后为全图可见（`visible/known = 全图`）。

### 背景音乐（程序化合成，零音频素材）
- **实现**：`packages/web/src/audio/music.ts` 用 WebAudio 振荡器 + 噪声实时合成，16 分音符步进音序器（25ms tick / 0.3s 前瞻排程），**不打包任何 mp3/ogg**（整个 APK < 1 MB 也有它一份功劳）。
- **作曲**：D 小调五声音阶（D F G A C），8 小节和弦循环 `Dm – Bb – F – C – Dm – Bb – Gm – A`；声部 = 铺底和弦（双失谐三角波）+ 行军低音（方波+低通）+ 弹拨旋律 + 鼓组（正弦底鼓 / 噪声军鼓 / 高通踩镲）。
- **三种情绪自动切换**：菜单（72 BPM，只有铺底+旋律）→ 对局（92 BPM，加低音与轻鼓）→ 紧张（108 BPM，低音驱动+强鼓+换旋律，终局或己方区域数不到领先者一半时触发）。切换发生在小节边界，不会突兀。
- **控制**：顶栏 🔊/🔇 一键静音；菜单里有「背景音乐」开关 + 音量滑块，设置存 `localStorage`（`gongfa-war.music` / `gongfa-war.volume`）。
- **礼仪与性能**：受浏览器自动播放策略限制，音频在**首次点击/按键**后启动（`AudioContext` 懒创建）；切到后台自动 `suspend()` 省电；开发态 HMR 下用全局单例复用同一个 AudioContext，避免多路音乐叠加。
- **可校验**：`renderOffline(mood, seconds)` 用 `OfflineAudioContext` 离线渲染波形（浏览器控制台即可跑），便于校验合成结果而不必"用耳朵听"。

| 小地图 | 常显 | 手机上**默认收起**（只留 全图 / 首都 / ▴ 一行，44px），点 ▴ 展开并记住选择；省下的 66px 全给地图 |
| 开局视野 | 首都 1.25× | 手机**自动适配「己方领土 + 相邻一圈」**（缩放下限 0.9，保证数字与图标可读），第一屏就看得清自己的地盘，而不是一条横带 |
| 区域名 | ≥1.25× 显示 | 显示阈值下调到 `cs ≥ 21`，自动适配后（约 0.9~1.35×）区域名照样显示 |
| 提示条 | 左下 | 手机上移到**屏幕下方中间**，不再压住左下角小地图 |
| 顶栏 | 行动/回合/季节 | 补上**「当前：🐉 秦（你）」**，中间不再是一条空白；屏宽 <760px 时自动隐藏该芯片（只留 行动/回合/季节） |

触屏操作（五处关键修复）：
- **点按只触发一次**：浏览器在触摸后会补发一套合成鼠标事件，早先版本一次点按被处理两次（先选中、再被当成「重复点击同一区域」取消），表现为**手机上点了没反应**。现在触摸后 700ms 内的鼠标事件一律忽略，并在 `touchend` 阻止默认行为。
- **去掉了「长按取消选中」**：手指稍慢就被判成长按，导致点按失效。取消选中改为：再点同一区域 / 点空白海域 / 右侧面板的「✕ 取消」。
- **选中后自动把该区域挪进可视区**（避开顶栏与右侧 30% 的详情面板），否则相邻区域常在面板后面而点不到 —— 这也是「无法调兵进攻」的直接原因之一。
- **弹窗永远在最上层**：弹窗 `z-index` 提到 60（高于详情面板的 30），并且打开弹窗时自动把面板滑走（`body.dialog-open`），不再出现"面板压住确认按钮"。
- **真·全屏**：Android 外壳用沉浸式全屏（API 30+ 用 `WindowInsetsController`，低版本用 `IMMERSIVE_STICKY`）隐藏状态栏与导航栏，并允许内容延伸到刘海区；另有一道保险 —— 若某机型又露出系统栏，WebView 会按 `WindowInsets` 自动让出对应高度，顶栏按钮不会被压住。
- 手势：单指拖拽平移、双指捏合缩放、轻点选中（手指抖动容差 14px）；画布按 `devicePixelRatio` 放大渲染，高分屏不糊。

### 季节与天气（天时）
- **四季循环**：每个大回合（所有势力各走一次）= 1 回合，**每 6 个大回合换一季**，一年 24 回合。

| 季节 | 效果 |
|---|---|
| 🌸 春 | 万物复苏：每区产兵 **+1** |
| 🌊 夏 | 雨季风浪：**跨海进攻额外 -1 骰** |
| 🍂 秋 | 秋收：**农场与平原产兵 +1** |
| ❄️ 冬 | 严冬：每区产兵 **-1**，**防守 +1 骰** |

- **天气**：每个大回合从当季合理的池子里重掷（冬天不下雨、夏天不下雪）：☀️晴朗 / 🌧️雨季（跨海 -1 骰）/ 🌫️大雾（进攻 -1 骰）/ 🌨️风雪（防守 +1 骰、产兵 -1）。
- 进攻骰最多扣 2 颗（避免完全打不动）；**战斗与弹窗预览共用同一套修正**，所以弹窗里的胜率就是真实概率，并写明「天时：大雾 进攻 -1 骰 · 冬 防守 +1 骰」。AI 评估也吃这套修正，不会在雨季硬冲跨海。
- 顶栏芯片显示当前季节/天气（悬停看完整说明），换季会写进战报。

### 事件卡（每 5 个自己的回合抽一张，共 10 张）
🌾丰收 · 📜征兵 · ☠️瘟疫 · 🪓蛮族入侵 · 🔥叛乱 · 🎁诸侯来朝（首都按区域数得兵）· 🛡️前线增援（与敌相邻区域 +3）· 🐎良马快枪（本回合 +3 行动）· 🏃逃兵（随机 3 区 -1）· ✨盛世（每座城池 +3）

### 成就（10 项，解锁后永久保存）
⚔️首战告捷 · 🕊️兵不血刃（零损失占领）· 👑擒贼擒王（占领首都）· ⚡闪电战（单回合占 3 区）· 🏴一方霸主（8 区）· 🏛️富甲一方（名下设施总数 ≥ 3，同区三种也算）· 🏙️大都会（4 座城池）· 🐢绝地翻盘（曾垫底仍统一）· 🌍一统天下 · ⏱️百日统一（60 回合内统一）

解锁时弹提示 + 成就音效；进度存 `localStorage`，列表在左栏 / 手机抽屉的「🏆 成就」面板（未解锁显示为锁）。

### 音效与震动（同样零素材）
- **音效**：`packages/web/src/audio/sfx.ts` 用振荡器 + 噪声合成 9 种音效 —— 轻点、选中、**进攻鼓点**（底鼓+噪声+下滑音）、战斗取胜、受阻低音、**占领音**、结束回合钟声、错误提示、**成就解锁**琶音。
- **震动**：进攻 `[18,40,22]`、占领 `[10,24,10,24,40]`、成就 `[16,40,16,40,60]`（WebView 需要 `VIBRATE` 权限，已加进 manifest）。
- 开关在菜单：**音效** 与 **震动** 各自独立（`localStorage: gongfa-war.sfx` / `.vibrate`），设置即时生效并提供试听。

### 区域显示（矢量图标版）
- **图标全部矢量**：`packages/web/src/render/icons.ts` 用 SVG 路径 + `Path2D` 绘制（含描边），缩放不糊、无需异步加载图片。共 13 个：🏰城池 / ⛏矿场 / 🌾农场 / 🌿平原 / 🌲森林 / ⛰山地 / 兵营 / 要塞 / 宝库 / 王冠 / 火焰 / 国旗（按国家色染色）/ **小兵**。
- **小兵图标**取自用户提供的 SVG（1206×1024，5 段路径）：按归属国**国家色的提亮版**染色 + 加粗深色描边，因此在同类色地块上也能"跳"出来；启动时用离屏画布自动量出人形墨迹范围并裁剪（原图长矛占了整个宽度，不裁剪会显得很小）。
- **数量显示在小兵头顶**：粗体数字 + 深色描边，任何底色都看得清。
- **其余信息分层摆放**：地形图标左上、国旗右上、特殊设施右下**竖排**（最多 3 个，各带金色脉冲环）、王冠左下（首都）、区域名在脚下；受威胁改为**脚下的红色脉冲椭圆**。
- **尺寸放大**：默认相机 1.25 倍（原来 1.0）；小兵宽度 `clamp(cs×1.18, 20, 60)`；缩到很小时进入 **LOD 精简模式**（只留头顶数字）。
- 左栏三块面板（势力 / 战报 / 成就）改为按比例分配高度并各自滚动，不再互相挤压。

### 界面与胜负
- **界面**：顶栏（回合 / 当前方 / 行动次数 / 季节天气 / 已解锁科技）；左侧**势力详情**（两行式：势力名 + 数据芯片）、**战斗记录**、**🏆 成就**；右侧**地块详情**（地名、类型、加成、待结算、相邻区域敌我兵力与海路标记、设施效果说明）。
- **小地图 + 视图控制**：左下角小地图（1 格 1 像素，含战争迷雾与当前视口框），点一下镜头就过去；旁边 `🗺️ 全图`（缩放到刚好装下整张地图）与 `🏰 首都`（回到自己首都）。手机会自动缩小并上移 toast 避让。
- **动画**：调兵/进攻时弹出浮动数字（源区 `-N`、目标区 `+N`、战斗损失、`占领 XX`）。
- **胜负（唯一胜利条件）**：**占领全图每一块区域**（含中立区）才算胜利 —— 把对手打光不算赢，还得把剩下的地全部拿下；全员出局则平局。
- **淘汰**：失去全部区域即出局，其余势力继续争夺中立区。
- **回合上限 130**：到点按积分排名结算（只是"到点结算"，不是胜利条件）。上限 60 → 100（胜利条件改成征服全图）→ **130**（设施可叠加后局变长，超时率从 50/40/32.5% 回落到 31.7/21.7/11.7%）。

### AI
- **个性**：按国家特质区分（蒙古 1.35 好战 / 宋 0.7 龟缩且防守 1.3 / 罗马均衡 …），影响进攻门槛与调兵积极性。
- **决策**：多点评分贪心（胜算 × 目标价值，城池 +25、特殊区 +18），并用**威胁评估**（相邻敌军总和 − 自身兵力）把后方兵力调往最危险前线。
- **难度**：简单（门槛 1.3×）/ 普通（1.0×）/ 困难（0.75× 且每区额外 +1 兵力）。

### 兵力上限
- **单区兵力不设上限**（早期为 99，现已取消）：增援、事件卡、占领收益都按实际数值累加，屯兵路线不再被硬顶。

### 调兵范围高亮
- 选中己方区域后，**调兵最大范围（3 跳内可达的己方区域）整体高亮**：1 跳（相邻）绿色实线 + 绿色底，2~3 跳金色虚线 + 金色底；可进攻的相邻敌方为红色。
- **悬停任意可调兵目标**会画出**行军路径**（金色虚线串起途经区域），弹窗里也标注「行军 N 格」。

## 🚀 快速开始

### 1. 安装依赖

```bash
npm install
```

> 首次安装后如提示 `esbuild` 安装脚本未授权，执行：`npm approve-scripts esbuild`

### 2. 配置后端（可选，但推荐）

复制 `.env.example` 为 `.env`，填入本机 MySQL 账号：

```bash
cp .env.example .env
```

```ini
PORT=3000
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=你的MySQL密码   # ← 必改
MYSQL_DATABASE=gongfa_war
REDIS_URL=redis://127.0.0.1:6379
```

数据库表结构会在后端启动时自动创建；也可手动执行 `db/schema.sql`。
若本机没有 MySQL/Redis，可 `cd db && docker compose up -d` 一键起容器。

> 后端不可用时会自动**离线降级**：游戏照常可玩，存档落到浏览器 localStorage，排行榜/战绩暂不可用。

### 3. 启动

```bash
npm run dev
```

- 🎮 游戏：<http://127.0.0.1:5272/>
- 🔌 API：<http://127.0.0.1:3000>（健康检查 `/api/health`）

> ⚠️ 请使用 `127.0.0.1` 而非 `localhost`（本环境 `localhost` 可能被其它服务占用）。

### 3.5 局域网联机（手机 + 电脑）

```bash
npm run lan               # = npm run build + 启动后端（监听 0.0.0.0:3000，同时托管网页 + /relay + /ws）
```

- 电脑上运行后，菜单里选「直连房间（锁步）」或「电脑服务器」，点「创建房间」得到 4 位房间码；
- 手机连**同一 WiFi**，浏览器打开 `http://<电脑IP>:3000/`（例如 `http://192.168.2.154:3000/`），输入房间码 → 房主点「开始对局」；
- 其余席位由 AI 填充，人类加入会把 AI 席位换成人类。

### 4. 测试与平衡

```bash
npm test                  # 单测 + 无头 AI vs AI 模拟 + API 测试
npm run build             # 前端生产构建
npm run balance -- 80     # 平衡性批量模拟（可传：局数 区数 AI数 剧本）
```

### 5. 打安卓安装包（APK）

前置：**JDK 17+（推荐 21）** + Android SDK（`platforms;android-35` / `build-tools;35.0.0` / `platform-tools`）。
SDK 目录二选一：设置 `ANDROID_HOME`，或把 SDK 放在仓库根的 `.android-sdk/`（本仓库当前就是这么放的，见 `.gitignore`）。

```bash
npm run android:keystore   # 首次：生成本地自签名 release keystore（android/keystore/gongfa.jks）
npm run android            # 出调试包 app-debug.apk
npm run android:release    # 出自签名发布包 app-release.apk
# 可选参数：--release / --skip-web（跳过 Web 构建）/ --clean
```

产物在 `android/app/build/outputs/apk/{debug,release}/`，脚本也会打印绝对路径与体积。
Windows 上一键脚本会自动：构建 Web → 灌入 `android/app/src/main/assets/www` → 写 `local.properties` → 调 Gradle。

## 📱 安卓 App（APK）

**安装**：把 `release/gongfa-war-1.0.7-release.apk`（约 **0.94 MB**）传到手机 → 允许「安装未知来源应用」→ 点击安装。首次启动即进菜单，**完全离线可玩**。同签名的旧版本可直接覆盖安装，存档不丢。另外附一个 `gongfa-war-1.0.7-debug.apk`（包名带 `.debug` 后缀，可与正式版**并存**，用于对照排查）。

| 项 | 说明 |
|---|---|
| 包名 / 版本 | `com.gongfawar.game` · **1.0.7**（versionCode 8）· minSdk **23**（Android 6+）· targetSdk 35 |

| 音乐 | `setMediaPlaybackRequiresUserGesture(false)`，点「开始游戏」即出声 |
| 图标 | 5 种密度 + Android 8+ 自适应图标（`scripts/gen-android-icons.mjs` 纯 Node 生成，无设计稿依赖） |
| 签名 | 本地自签名（`android/keystore/gongfa.jks`，别名 `gongfa` / 口令 `gongfa2026`）——仅供自用/侧载；上架应用商店需换成正式签名 |
| 后端 | App 内没有 Node 服务端：排行榜/云存档会静默降级为本地存档；联机走内置中继或电脑上的 `npm run lan` |

> 为什么不用 Capacitor/Cordova？本项目只有一个 Canvas 页面、不需要任何原生插件，纯 WebView 外壳体积从 ~3 MB 降到 <1 MB，且没有 npm 侧依赖。

## 📝 设计要点

- **客户端权威（v1）**：单机回合逻辑在前端跑；存档/战绩/排行榜走后端；联机时再切服务端权威。
- **确定性**：区域生成（模板 + Voronoi 种子）、骰子战斗、事件卡抽取均使用种子随机（`rng.ts`），可复现、可测试。
- **可序列化**：完整游戏状态可 `serialize()` / `Game.deserialize()` 往返（`STATE_VERSION` 校验 + 字段兼容补齐），支撑存读档与未来回放/联机。
- **战争迷雾（轻量）**：视野 = 己方 + 相邻一圈；`Player.seen` 只增不减地记录探索历史，已探索区域保留地形/地名但隐藏兵力（`?`）。势力总兵力改为「已探索 ≈ 统计」。**AI 不使用迷雾**（全知），因此平衡模拟与 AI 难度**不被迷雾扰动**；迷雾是纯前端可关的展示层 + 一份 `seen` 状态。
- **零素材音频**：背景音乐全部由振荡器合成 —— 没有音频文件、没有版权问题、可随参数调节；代价是"电子音"风格而非真实配乐。
- **一套代码三个壳**：同一份 Web 产物分别以 **网站 / PWA / Android WebView** 三种方式加载；`packages/core` 仍是纯逻辑，App 外壳只负责"把页面塞进 WebView"，规则改动不需要动安卓工程。
- **公平起始**：先认领全部玩家首都，再分配初始领区（不足时向外扩），保证各家起点一致。
- **连通性保证**：陆地被海洋切开时，自动用最短「海路」连接各大陆并记录为 `seaNeighbors`，既保证可玩性又支撑「跨海 -1 骰」玩法。
- **反滚雪球**：领地加成采用「稀释 + 封顶」，并对区域数最少的势力给劣势补贴。
